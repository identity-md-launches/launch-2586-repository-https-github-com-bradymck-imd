# Test vectors

`bls12.json` is generated offline by `scripts/gen_bls12_vectors.mjs` and committed, because
the Foundry profile forbids `ffi` and network access. Its `provenance` object records the
generator and the libraries used.

- **Independent implementation:** `@noble/curves` 2.4.0 (`bls12-381`: RFC 9380 hash-to-curve,
  pairing, short-signature verification) with `@noble/hashes` 2. Nothing in the generator calls
  the Solidity code.
- **RFC 9380:** Appendix J.9.1 (`BLS12381G1_XMD:SHA-256_SSWU_RO_`, five messages with
  `u[0]`, `u[1]`, `Q0`, `Q1`, `P`) and K.1 (`expand_message_xmd` SHA-256, ten cases), parsed
  from the RFC text and cross-checked against noble before being written.
- **Signatures:** 109 valid group signatures (rounds 1–100, epoch boundaries 2880/2881 and
  5760/5761, round 120, 10⁶, 2³², `maxRound - 1` and `maxRound`), each with the 96-byte submit
  form, the 48-byte compressed form and `R = SHA256(compressed)`. Both compressed sign bits occur.
- **Threshold fixture:** 3-of-4 Shamir sharing of the group secret (share `i` at point `i + 1`),
  public shares, partial signatures and every 3-subset's Lagrange coefficients; all subsets
  reconstruct the same group signature.
- **Negative vectors:** infinity, a non-subgroup G1 point, an off-curve point, non-canonical
  coordinates, the negated signature, signatures under another key / another network id / a
  wrong epoch field, and group keys that are infinite, non-canonical, non-subgroup or in the
  wrong coefficient order.

**All keys are TEST-ONLY and NON-PRODUCTION.** They are SHA-256 of public labels so that
anyone can regenerate the fixture; they protect nothing and must never be used for a network.

To regenerate: install `@noble/curves@2.4.0` and `@noble/hashes@2` in a scratch directory,
download `rfc9380.txt` from the RFC Editor, then run
`NODE_PATH=<scratch>/node_modules node scripts/gen_bls12_vectors.mjs <path>/rfc9380.txt`.

## blst cross-check and bitmap-boundary signatures

`blst-crosscheck.json` is generated by `generate_blst_crosscheck.py`, using **blst 0.3.16**
through the pinned **pyblst 0.3.15** wheel. This is independent of both Solidity and noble.
The generator reconstructs the message directly from the network id and round, derives the
public key with blst, signs and checks every pairing with blst, and compares all 109 original
signatures, messages, affine/compressed encodings and SHA-256 values byte for byte. It also
cross-checks all five RFC J.9.1 points and every 3-of-4 threshold reconstruction.

Six additional valid signatures cover rounds **255, 256, 257, 511, 512, 513**. Foundry tests
publish them out of order, check the exact bitmap words, test duplicates, and use them in
stateful campaigns. All original vectors remain unchanged. The JSON provenance pins the
upstream blst revision, wheel SHA-256, and SHA-256 of the original noble fixture.

Regenerate entirely offline on CPython 3.12 / Linux x86_64:

```sh
python3 -B test/vectors/generate_blst_crosscheck.py
```

The required native wheel files, licence notices and binding source are ordinary files in
`vendor/pyblst/`; see its `README.provenance.md`. No package installation is required.
**Forge consumes only JSON**, so building and testing the contracts has no Python/native
module/platform requirement, and never invokes this generator or uses FFI.

## Field-reduction boundary oracle

`field-edges.json` is generated with Python's arbitrary precision integer remainder,
independently of MODEXP and Solidity. Cases include zero, one, p−1, p, p+1, 2p±1,
2^384−1, 2^511 and 2^512−1. The Solidity tests also embed each 64-byte integer between
sentinels and reduce from a nonzero offset.

```sh
python3 test/vectors/generate_field_edges.py
```

This generator uses only Python's standard library. Both generators use exclusively public,
NON-PRODUCTION fixtures; nothing here supplies deployment configuration or production keys.
